## r11s LineageOS — KernelSU-Next + SUSFS v2.1.0

Fixes the recurring KernelSU-Next Manager version-compatibility problem
for good by changing *how* `KSU_VERSION` is produced, instead of
chasing another one-off number.

### The problem with commit-pinning

v2.0.0 pinned KernelSU-Next to a specific commit on `pershoot/KernelSU-Next`'s
`dev-susfs` branch, copied in as a plain file tree (no `.git`). That forced
the build onto Kbuild's fallback path, which just bakes in whatever number
we hardcode:

- Pinning to the original commit's git-computed value (`30200`) worked
  until upstream's `dev-susfs` branch got rebased and that commit became
  unreachable. Re-cloning picked up a new HEAD and a naive recompute gave
  `33274` — *higher* than the Manager app installed on-device, so Manager
  refused to work with it ("needs 33274 or higher").
- Reverting to the hardcoded `30200` fixed that, but the Manager app had
  since updated, and `30200` was now *lower* than what the current Manager
  expected — the opposite failure.

Hardcoding a fallback number is fundamentally a snapshot of a moving
target. It will always eventually drift out of sync with whatever Manager
build the user has installed, in either direction.

### The fix: let KernelSU-Next compute its own version, live

KernelSU-Next's own `kernel/Kbuild` already has a proper mechanism for
this — it was just never able to run, because our archived copy had no
`.git` directory:

```
BASE_BRANCH := (current branch name with any "-suffix" stripped, e.g. dev-susfs -> dev)
BASE_COMMIT := git merge-base HEAD origin/$(BASE_BRANCH)
KSU_GIT_VERSION := git rev-list --count $(BASE_COMMIT)
KSU_VERSION := 30000 + KSU_GIT_VERSION
KSU_VERSION_TAG := git describe --tags --abbrev=0 $(BASE_COMMIT)
```

This is the same formula the actual upstream release builds (and Manager
app builds) use, so as long as both sides track the same upstream lineage,
they stay compatible automatically — no manual number-picking required.

Changes in this release:
- **CI now clones `pershoot/KernelSU-Next` (`dev-susfs`) fresh, with full
  history, at the start of every build** (`build.yml` and `release.yml`),
  instead of building from a stale copy baked into the repo. This is what
  "use the release source instead of a pinned commit" means in practice:
  KernelSU-Next has no dedicated GitHub Release for the `dev-susfs`
  variant (only the base `dev`/`stable` line is tagged, and those tags
  predate the SUSFS driver integration), so the closest correct
  equivalent is always building against upstream's current state and
  letting its own version machinery compute the number — the same way an
  official release build would.
- Removed the hand-maintained `KSU_VERSION_FALLBACK` / `KSU_VERSION_TAG_FALLBACK`
  overrides from `kernel/Kbuild`. The archived `kernel_source/KernelSU-Next/`
  in this repo is back to stock and is a point-in-time snapshot only — the
  actual build always re-fetches live.
- This build's computed version: `KSU_VERSION = 33264` (`git rev-list --count`
  at the merge-base of `dev-susfs` with `dev`, which was at `v3.3.0`).
