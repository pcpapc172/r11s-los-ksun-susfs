## r11s LineageOS — KernelSU-Next + SUSFS v2.1.0

Updates KernelSU-Next to track upstream's `v3.4.0` line.

### What changed

`pershoot/KernelSU-Next`'s `dev-susfs` branch has been rebased onto
upstream's `v3.4.0` tag (7 commits past it — SUSFS/`ksud` fixes on top).
Note that the plain `v3.4.0` git tag itself does **not** contain SUSFS —
it lives on the base `dev` line; `dev-susfs` is the rolling branch that
carries SUSFS on top of whichever `dev` tag it was last rebased onto.
This release builds from `dev-susfs` HEAD (commit `b898689b`), which is
downstream of `v3.4.0` — same approach as v2.0.0, just picking up two
weeks of upstream progress.

Since CI (and this rebuild) clone KernelSU-Next fresh rather than
pinning a commit, `KSU_VERSION` is computed live as always:
`KSU_VERSION=33301`, `KSU_VERSION_TAG=v3.4.0`.

### Manager APKs

Replaced the bundled `manager_apk/*.apk` files with fresh builds from
upstream `KernelSU-Next/KernelSU-Next`'s own CI
([run #1963](https://github.com/KernelSU-Next/KernelSU-Next/actions/runs/35684922501)),
built at commit `d3c68954` — the exact merge-base commit this kernel
build's `KSU_VERSION` calculation resolves to. Same pairing logic as
v2.0.0: kernel and Manager both derive their version number from the
same upstream commit, so they agree without any manual pinning.

### Validation

Re-ran the full check against all 324 `.ko` files from the real
`vendor_boot` ramdisk:
- CRC mismatches: **0**
- Symbols with a CRC record but missing from the actual ksymtab lookup
  table: **0**
- Total refs checked: 16560 (1971 expected inter-module deps, same as
  every previous build)
