## r11s LineageOS — KernelSU-Next + SUSFS v1.0.0

First stable release. LineageOS 23.2 kernel (Linux 5.10.260) for the
Samsung Galaxy S23 FE (`r11s`, SM-S711B, Exynos 2200), built from
ExtremeXT's `android_kernel_samsung_s5e9925` source with KernelSU-Next
and SUSFS integrated.

### What's in it

- **KernelSU-Next**: `pershoot/KernelSU-Next`, `dev-susfs` branch (v3.3.0-based)
- **SUSFS**: v2.3.0 (`simonpunk/susfs4ksu`, `gki-android12-5.10` branch),
  with two upstream fix commits from `pershoot/susfs4ksu` cherry-picked in
- Base `.config` extracted directly from a known-working ExtremeXT
  KSUN-only `boot.img` to minimize unrelated config drift, with
  `CONFIG_KSU`, `CONFIG_KSU_SUSFS` and sub-options, overlay/tmpfs support
  enabled on top

### The bug this release fixes

Earlier builds panicked immediately on boot:
```
usb_notify_layer: Unknown symbol usb_disable_autosuspend (err -2)
init: Failed to load kernel modules
Kernel panic - not syncing: Attempted to kill init!
```

**Root cause**: `CONFIG_TRIM_UNUSED_KSYMS` was silently stripping the
`__ksymtab` export entry for `usb_disable_autosuspend`. The symbol's CRC
record survived (so a naive CRC check looked fine), but the actual
symbol-lookup entry `insmod` needs did not — because `usb_notify_layer.ko`
is a proprietary Samsung blob living in `vendor_boot`, entirely outside
this open-source kernel tree, so the trimmer's "what's actually used"
analysis had no way to know it was needed.

**Fix**: `CONFIG_TRIM_UNUSED_KSYMS` disabled entirely, so every
`EXPORT_SYMBOL`/`EXPORT_SYMBOL_GPL` is kept regardless of whether this
build's own module list references it.

An intermediate attempt disabled `CONFIG_MODVERSIONS` instead (bypassing
symbol version checks entirely). That build got further into boot but
then hit a livelock — 7 of 8 CPU cores frozen inside `do_futex`, forcing
a hardware watchdog reset — most likely because disabling that check let
a genuinely-incompatible module load silently instead of failing safely.
`MODVERSIONS` is back on in this release.

### Validation

All 324 `.ko` files were extracted from the real `vendor_boot` ramdisk
and checked against this build's `vmlinux`:
- CRC mismatches: **0**
- Symbols with a CRC record but missing from the actual ksymtab lookup
  table (the exact class of bug above): **0**

`vendor_boot` is never modified by the flashable zip — only the `boot`
partition (kernel `Image`) is replaced.

### CI

This is the first release built and validated through GitHub Actions.
Every push to `main` now runs the same build + the
`usb_disable_autosuspend` export regression guard automatically.
